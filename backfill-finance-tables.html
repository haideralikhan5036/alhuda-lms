Finance Tables Backfill

Before you start: This tool copies existing fee and salary records into the new finance tables. It never changes or deletes the existing records. Run a dry-run first. Keep the fee_tables_v1 flag OFF while backfilling.

Finance tables flag (fee_tables_v1)

When this flag is ON, every new fee and salary slip also writes a copy into the new finance tables. Keep it OFF while backfilling. After changing it, refresh any open portal page — portals read the flag once when they load.

Step 1 — Load sources

Reads every family's stored fee history and every teacher's stored records from the database, plus this browser's local fee records (alhuda_fee_records) and salary cache (alhuda_teacher_salaries), and the shared salary carrier stored in a family's notes.

Step 2 — Dry-run (writes nothing)

Builds the full migration plan — including duplicate receipt-number handling and quarantined records — and checks that every total reconciles before anything is written.

Step 3 — Write to tables

Available only when the dry-run reconciles. Writing is insert-only and idempotent: records already in the tables are detected and skipped, so an interrupted run is safe to repeat. If a record fails, the run stops at that record and tells you which one and why.

Step 4 — Verify

Re-reads the finance tables and compares them with the plan, total by total. You can run this before writing too — expect FAIL lines until the write run has completed.

Rollback: nothing in the portals reads these tables yet. A bad run is corrected by fixing the plan and re-running; rows are never deleted by this tool.
